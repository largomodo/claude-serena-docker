# CLAUDE.md

Shell scripts that run inside the container at startup and runtime.

## Index

| File                | Contents (WHAT)                                                                                                                                     | Read When (WHEN)                                              |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `init-workspace.sh` | ENTRYPOINT: variant-aware init via VARIANT env var; the variant case table owns LANG_GLOBS, BINARY_EXTENSIONS, SERENA_MAX_ATTEMPTS, MULTI_LANG, CREATE_GHIDRA_PROJECTS_DIR, REGISTER_KICAD_MCP, REGISTER_REA_MCP, REA_MCP_ENV_VARS (names of image ENV variables passed to the rea MCP entry), START_ADB_RELAY and BINARY_ANALYSIS_HINT; populates bind-mounted dirs; two-tier failure policy (template copies and the first claude-config clone are fatal, Serena/MCP steps warn via `warn()`); first-launch `.claude.json` persistence armed from the `CLAUDE_JSON_MOUNTED` variable launch.sh sets; Serena indexing, MCP registration (`register_serena_mcp`: remove-then-add, `--context claude-code`; `register_rea_mcp` for x86/68k/android: remove-then-add `rea mcp` with the REA_MCP_ENV_VARS values and the compact schema profile, plus a per-launch copy of REA's bundled skill into ~/.claude/skills, left untracked in the claude-config checkout), `start_adb_relay` (android: loopback socat relay 127.0.0.1:5037 to ADB_HOST_SERVER, warn-only on failure), `.claudeproject/.gitignore` written when missing, `relocate_serena_index_logs` moving Serena's hard-coded `<root>/.serena/logs` under `.claudeproject/serena` when no legacy `.serena/project.yml` exists; one `detect_languages` loop (first match, or collect-all under MULTI_LANG for java-angular with the angular-subsumes-typescript rule) | Debugging container startup, changing init sequence, modifying variant-specific language detection, modifying multi-language detection, changing the failure policy or the first-launch handoff |
| `start-dockerd.sh`  | ENTRYPOINT for the image-dev and java-docker variants; starts rootless `dockerd`, exports `DOCKER_HOST` derived from the runtime UID, polls for daemon readiness, then execs `init-workspace.sh`. Shared by both variants. | Debugging rootless Docker daemon startup, changing DinD readiness polling, modifying `DOCKER_HOST` resolution |
| `trafilatura-ua.sh` | Build-time step in Dockerfile.base: looks up the current Chrome stable major from Google's Chrome for Testing endpoint and rewrites one line of the installed trafilatura (`DEFAULT_HEADERS["User-Agent"]` in downloads.py) plus `USER_AGENTS` in its settings.cfg, so plain `trafilatura -u`, the Python API, and feed/sitemap discovery pass UA-based bot blocks without flags. Falls back to a pinned Chrome major if the lookup fails; fails the build with a diagnostic if the target line is gone or the effective header is wrong (`TRAFILATURA_UA_PATCH=skip` overrides). `--check <venv-python>` prints the effective UA at runtime | Debugging 403s from trafilatura, a base build failing at the user-agent step, changing the UA string or version source |
| `web-fetch.sh`      | Runtime front end for the web-fetch skill, installed to /usr/local/bin: `web-fetch.sh <url> [trafilatura flags]` walks a fallback ladder (trafilatura live, curl with the same Chrome UA piped into trafilatura, newest Internet Archive `id_` snapshot fetched with `--compressed`), drops the URL fragment, recognises Cloudflare/JavaScript challenge pages by signature, prints markdown to stdout and one `web-fetch:` status line to stderr naming the winning stage and archive snapshot date; exit 1 with reasons and the buffered trafilatura log when every stage fails. `MIN_BYTES` (default 200) sets the success threshold | Debugging a page fetch that fails or silently comes from the archive, changing the fallback order, adding a challenge-page signature, modifying the web-fetch skill |
| `check-tools.sh`    | Build-time guard run by Dockerfile.base and every variant Dockerfile: verifies each binary and variable named in the tool sheets' `## Tools` / `## Environment` tables exists; fails the build with the missing names. Also runs standalone inside a running container as `check-tools.sh ~/.claude/claude-env.md` to confirm the installed sheet still matches the image | A build fails at the check-tools step, adding or removing a tool from a Dockerfile, changing the sheet format |
| `freeroute.sh`      | Headless freerouting wrapper: `freeroute <input.dsn> <output.ses> [max_passes] [extra args]` runs /opt/freerouting/freerouting.jar with `-Djava.awt.headless=true` | Debugging autorouting runs, changing freerouting arguments |
| `kicad-autoroute.sh` | One-command board autoroute: `kicad-autoroute <board.kicad_pcb> [max_passes]` exports DSN, runs freerouting, imports SES, saves `<board>-routed.kicad_pcb` beside the input; the original board is never modified | Debugging the KiCad autoroute pipeline, changing output naming |
| `kicad_specctra.py` | pcbnew SWIG helper run with the MCP venv Python: `export <board> <out.dsn>` and `import <board> <in.ses> [out]`, since kicad-cli has no Specctra subcommand | Changing DSN export or SES import behavior |

`REA_MCP_ENV_VARS` in the case table lists variable names, not values, so the registered REA env stays single-sourced in each Dockerfile's ENV.
