# Snippets

Variant-specific resources copied into variant Docker images via COPY instructions. These are not shared across all images — shared infrastructure (apt packages, Serena, cli-tools, codeuser setup) lives in `Dockerfile.base`. This directory holds only resources that belong to one or two variants.

## Directory Layout

- `shared/` holds two groups. Binary helpers (dis16.sh, r216.sh, dump16.sh) are used by both `Dockerfile.snes` and `Dockerfile.x86`. Java toolchain install scripts are used by the JDK-bearing variants: `install-jdk.sh` by java, java-docker, java-angular, x86, snes, 68k, kicad and android; `install-jdtls.sh` and `install-lombok.sh` by the three java variants. `install-ghidra.sh` is used by x86, snes, 68k and android and `install-rea.sh` by x86, 68k and android; their pins are the `x-ghidra-toolchain` and `x-rea-toolchain` anchors in docker-compose.yml. Sharing rule: a Dockerfile step that two or more variants run identically lives here as a script taking its pins as arguments, so pins stay in docker-compose.yml or the variant Dockerfile ARG defaults while the script owns the URL templates and the procedure exists once. Dockerfiles COPY the scripts into the image at `/usr/local/share/claude-env/install/` and run them with bash. Argument contract: arguments are positional, with a fixed count and order per script: `install-jdk.sh <java_lang_version> <adoptium_version> <adoptium_build> [target_dir]` (optional fourth argument, default `/opt/java/openjdk`; `Dockerfile.snes` passes `/tmp/gradle-jdk` for its build-only JDK 21), `install-jdtls.sh <jdtls_version> <jdtls_timestamp> <jdtls_sha256>`, `install-lombok.sh <lombok_version> <lombok_sha256>`, `install-ghidra.sh <ghidra_version> <ghidra_date> <ghidra_sha256>`, `install-rea.sh <rea_version> [keep-frida]` (optional literal second argument keeps REA's frida module; android passes it). A wrong count or an empty argument (including an empty `target_dir`) prints a usage line to stderr and exits 2, so an unset compose/ARG pin fails the build instead of producing a malformed URL. Dockerfiles invoke `bash <script>` rather than executing the file directly because the executable bit that COPY preserves depends on the checkout and host file mode (it can be lost on some hosts or filesystems), and a chmod layer would add cost for no gain.
- `snes/` resources are specific to the SNES analysis variant only.
- `android/` holds launcher wrappers COPY'd to /usr/local/bin. Each exists because upstream's launcher is replaced (apktool), a persisted cache directory must exist first (blutter) or a runtime setting is required (il2cppdumper: the net7 build needs `DOTNET_ROLL_FORWARD=Major` to start on Ubuntu 26.04's only .NET runtime, 10.0, and its config.json carries `RequireAnyKey=false` so a headless shell never blocks on a keypress).
