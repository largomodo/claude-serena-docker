# claude-env container toolchain: x86

## Tools (x86)

| Tool | What | Use when |
| --- | --- | --- |
| `nasm` `ndisasm` | Netwide Assembler and disassembler | Assembling or disassembling x86/DOS code |
| `r2` | radare2 | Interactive binary analysis, scripting |
| `upx` | UPX packer/unpacker | Unpacking a compressed executable |
| `analyzeHeadless` | Ghidra 12.1 headless (/opt/ghidra) | Batch import and auto-analysis of a binary |
| `rea` | REA CLI, same engine as the `rea` MCP server | Scripted decompile/xrefs from a shell |
| `dis16` `r216` `dump16` | 16-bit real-mode wrappers for ndisasm, r2, objdump | Disassembling or hex-dumping real-mode code |

## Environment (x86)

| Variable | What |
| --- | --- |
| `VARIANT` | Container variant name (`x86`) |
| `JAVA_HOME` | JDK installation root |
| `GHIDRA_INSTALL_DIR` | Ghidra root for REA |

## MCP servers (x86)

| Server | What |
| --- | --- |
| `rea` | Ghidra-backed: open_binary, list_procedures, analyze_function, xrefs |

## Notes (x86)

- Binary analysis variant: no Serena project; Serena file tools still work.
- Prefer `rea` tools over analyzeHeadless for MZ/COM/PE/ELF; read /usr/local/share/claude-env/tools/rea-notes.md first.
- `capstone` and `pefile` import from /opt/cli-tools/.venv/bin/python.
- Presence on PATH is what the build verifies, not that a tool succeeds.
