# claude-env container toolchain: x86

## Tools (x86)

| Tool | What | Use when |
| --- | --- | --- |
| `nasm` `ndisasm` | Netwide Assembler and disassembler | Assembling or disassembling x86/DOS code |
| `r2` | radare2 | Interactive binary analysis, scripting |
| `upx` | UPX packer/unpacker | Unpacking a compressed executable |
| `analyzeHeadless` | Ghidra 12 headless (/opt/ghidra) | Batch import and auto-analysis of a binary |
| `dis16` `r216` `dump16` | 16-bit real-mode helpers wrapping ndisasm, r2 and objdump | Disassembling or hex-dumping 16-bit real-mode code |
| `java` | JDK, required by Ghidra | Debugging a Ghidra headless launch failure |

## Environment (x86)

| Variable | What |
| --- | --- |
| `VARIANT` | Container variant name (`x86`) |
| `JAVA_HOME` | JDK installation root |

## Notes (x86)

- Binary analysis variant: no Serena project is created, but Serena's file tools still work.
- `capstone` and `pefile` are importable from /opt/cli-tools/.venv/bin/python.
- Ghidra projects go under a directory the caller chooses; there is no fixed GHIDRA_PROJECTS_DIR for this variant.
- Presence on PATH is what the build verifies; it does not guarantee a listed tool succeeds for every invocation.
