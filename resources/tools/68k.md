# claude-env container toolchain: 68k

## Tools (68k)

| Tool | What | Use when |
| --- | --- | --- |
| `vasmm68k_mot` | 68000 assembler, Motorola syntax | Assembling 68000/Neo Geo code |
| `vasmz80_mot` | Z80 assembler | Assembling Z80 code |
| `vlink` | Linker for vasm output | Linking assembled object files |
| `mame` | Neo Geo / 68k emulator (/usr/games) | Running or debugging a built ROM |
| `analyzeHeadless` | Ghidra 12.1 headless (/opt/ghidra) | Batch import and auto-analysis of a ROM |
| `rea` | REA CLI, same engine as the `rea` MCP server | Scripted decompile/xrefs from a shell |

## Environment (68k)

| Variable | What |
| --- | --- |
| `VARIANT` | Container variant name (`68k`) |
| `JAVA_HOME` | JDK installation root |
| `GHIDRA_INSTALL_DIR` | Ghidra root for REA |

## MCP servers (68k)

| Server | What |
| --- | --- |
| `rea` | Ghidra-backed analysis of headerless 68000 images: functions, pseudocode, xrefs |

## Notes (68k)

- Serena has no assembler LSP; `.asm` files are not indexed (Python/Go/Rust/TS helpers are).
- MAME is headless-only here (no display): automated runs and debugger scripts.
- A built P-ROM is headerless: open it as raw-binary, architecture m68k, at its load address; read /usr/local/share/claude-env/tools/rea-notes.md first.
- Presence on PATH is what the build verifies, not that a tool succeeds.
